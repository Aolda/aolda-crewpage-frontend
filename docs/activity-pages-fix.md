# Activity 목록·상세 접속 오류 수정

## 원인

- 운영 프로젝트 목록은 UUID ID와 `background`를 반환하며, 선택적인 `backgroundImage`는 반환하지 않는다. 현재 22건의 배경 URL이 비어 있어 `backgroundImage.url` 직접 접근이 목록 렌더링을 중단시켰다.
- 상세 라우트가 UUID를 `Number()`로 변환한 뒤 truthy 여부를 검사하여, 요청 없이 로딩 화면에 남았다.
- 상세 라우트에 `USE_MOCK = true`가 남아 있었고 상세 템플릿도 같은 이미지 접근 오류를 가지고 있었다.

## 변경

- 프로젝트 ID를 문자열로 통일하고 UUID 형태를 확인한 뒤 실제 상세 API를 호출한다. 숫자 ID용 예시 목록도 UUID 형식으로 변경했다.
- 목록·상세 이미지에 공통 대체 로직을 적용한다. `background.url` → 레거시 `backgroundImage.url` → 기존 로컬 마스코트 순서로 표시한다.
- 상세의 프런트엔드 mock 분기를 제거한다. 약칭이 없는 활동의 제목은 영문명/한글명으로 대체한다.
- 잘못된 주소, 404, 네트워크/서버 오류에 안내와 목록 링크를 표시하고 조회 실패는 재시도할 수 있게 한다. 페이지 이동/재시도 후 도착한 이전 응답은 무시한다.
- 백엔드, DB, 운영 환경, 인증 및 기존 배포 전용 호환 패치는 변경하지 않는다.

## 검증 (2026-08-28 KST)

- `npm run test:activity`: 9개 통과. UUID 전달, API 응답/404 전달, 빈 이미지, 레거시 이미지, 카드·상세 렌더링, 오류 안내를 검증한다. 합성 데이터만 사용하며 운영 데이터 쓰기는 없다.
- `npm run test:crew-academic`: 기존 3개 통과.
- 변경된 TS/TSX 파일 대상 ESLint 및 `git diff --check`: 통과.
- 로컬 Next 개발 서버에서 `/api` 프록시를 운영 공개 API로 연결하여 브라우저 검증: 목록 22건, AAS 카드 클릭 → 실제 UUID 상세 표시, 같은 상세 주소 직접 재접속, 잘못된 ID 안내, 미존재 UUID 오류 안내·재시도·목록 복귀.
- `npm run build`: 컴파일 성공, 기존 `Badge.styles.ts`의 `RECRIUTING` 타입 오류로 타입 검사 단계 실패. `tsc --noEmit --incremental false` 기준 수정 전 10건 → 수정 후 8건이며, 나머지는 기존 Badge/홈페이지/예시 데이터 오류다. 타입 검사 우회 설정은 추가하지 않았다. 개발 서버 검증을 정식 프로덕션 빌드 통과로 간주하면 안 된다.

## 별도 후속 검토 사항 (이번 수정 범위 밖)

- 백엔드는 존재하지 않는 UUID에 현재 404가 아닌 500을 반환하므로 운영에서는 일반 조회 실패 문구가 표시된다. 404 문구는 합성 응답 기반 테스트로 검증했다.
- 백엔드 상세 응답 자체가 `PROJECT_DETAIL_EXAMPLE`의 프로젝트 유형·진행회차·갤러리를 일부 사용한다. 프런트엔드 mock 제거는 이 백엔드 예시 값까지 제거하지 않는다.
- 상세 참여자 배열은 백엔드의 관리자 override 기준이며 목록 참여자 집계와 차이가 있을 수 있다. 기존 어두운 테마의 상세 헤더 글자 대비도 별도 검토가 필요하다.

## 운영 반영 조건

사용자의 PR 승인 및 main 병합 확인 전에는 운영 반영하지 않는다. 이후에도 실제 병합 diff와 운영 SHA를 비교하고 기존 프런트엔드 호환 빌드 패치와 `/api` 빌드 환경값을 보존한다. 이 수정에는 백엔드 배포나 DB 작업이 필요 없다.
